# Acceso de clientes

Rama feat/auth-clientes basada en feat/payments-profile-history. Backend debe ejecutar feat/gestion-estacionamiento (b345ec6 o posterior), MySQL y seed demo. En frontend npm run build, npm test y npm run dev -- --host 0.0.0.0. No dependencias nuevas.

La primera visita a Inicio y el cierre de sesión voluntario desde Perfil llevan a /inicio-carga (splash visible 1,6 s, sin navegación inferior) y luego a /bienvenida. Desde allí se puede iniciar sesión o continuar como invitado. Recargar con sesión vigente conserva la sesión sin repetir la bienvenida; /bienvenida siempre accesible manualmente. Login y registro separados. Invitados ven Inicio, Espacios y Seguridad; perfil público ofrece login. Rutas personales protegidas. API por proxy Vite /api/auth, /api/usuarios, /api/vehiculos; despliegue real requiere proxy HTTPS. JWT y vencimiento en sessionStorage por pestaña, restauración mediante GET /auth/me, expira en una hora, 401 cierra sesión. Una falla de red permite reintentar sin perder el token. No se guarda perfil ni contraseña, ni tokens en localStorage. sessionStorage es accesible por JavaScript y no garantiza persistencia tras cerrar pestaña; para producción migrar a sesión/renovación con cookie HttpOnly Secure y HTTPS. No compartir credenciales reales en HTTP de feria.
